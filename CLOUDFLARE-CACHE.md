# Кеш статики в Cloudflare — что и зачем настроить

Заметка к настройке, которой нет в коде: заголовок `Cache-Control`
ставит Cloudflare, а не сайт (файлов `_headers` / `.htaccess` в
репозитории нет).

## Что сейчас

Проверено `curl -I` 16.11.2026:

| Что | Cache-Control | Оценка |
|-----|---------------|--------|
| `redesign.css?v=379`, `redesign.js?v=379` | `max-age=14400` (4 ч) | можно год |
| `image/*.webp?v=379` | `max-age=14400` | можно год |
| `fonts/*.woff2` (без версии) | `max-age=14400` | можно год |
| `image/favicon.*`, `apple-touch-icon.png` (без версии) | `max-age=14400` | **оставить как есть** |
| HTML-страницы | `max-age=600` (10 мин) | **не трогать** |

Lighthouse предлагает «Use efficient cache lifetimes» — экономия
170 КиБ на повторных заходах.

## Почему это стало безопасно только теперь

До 16.11.2026 картинки подключались **без** `?v=`, и длинный кеш
означал бы, что заменённое фото не дойдёт до вернувшегося
посетителя месяцами. Так и вышло после выкладки редизайна: сервер
отдавал новое фото, а в браузере висело старое, в жёлтой каске.

Теперь версия проставляется автоматически (`bump-version.py`,
список `ASSETS`), адрес файла меняется при каждой правке — и
длинный кеш больше ничего не «запирает».

⚠️ **Порядок обязателен:** сначала версионирование, потом длинный
кеш. В обратном порядке старые файлы закрепятся у посетителей на
весь срок.

## Что настроить

Панель Cloudflare → домен `mastera.ge` → **Rules** → **Cache Rules**
→ Create rule.

**Правило «Статика — год»**

Условие (Custom filter expression):

```
(http.request.uri.path.extension in {"css" "js" "webp" "woff2" "jpg" "png" "svg"}
 and not starts_with(http.request.uri.path, "/image/favicon")
 and not starts_with(http.request.uri.path, "/image/apple-touch-icon")
 and not starts_with(http.request.uri.path, "/image/web-app-manifest"))
```

Действия:
- Cache eligibility → **Eligible for cache**
- Edge TTL → Override origin → **1 year**
- Browser TTL → Override origin → **1 year**

**Чего НЕ делать:**

- Не включать правило для HTML и `/` — страницы должны обновляться
  быстро, иначе правка текста или цены не дойдёт до посетителей.
  Нынешние 10 минут менять не нужно.
- Не включать фавиконки и web-app-manifest: они подключаются без
  `?v=` намеренно (лишний параметр в `<link rel="icon">` некоторые
  читалки манифеста понимают плохо), поэтому длинный кеш для них
  закрепит старую иконку.
- Не трогать `sitemap.xml` и `robots.txt` — их читают поисковики.

## Как проверить, что применилось

```
curl -sI "https://mastera.ge/redesign.css?v=379" | grep -i cache-control
```

Ожидается `max-age=31536000`. Для фавиконки
(`/image/favicon.svg`) должно остаться прежнее значение.

Первый запрос после настройки может показать старый заголовок из
кеша Cloudflare — повторить через минуту или добавить к адресу
произвольный параметр.
