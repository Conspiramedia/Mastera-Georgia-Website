## 1.1. Core Web Vitals: LCP 1988 мс — шрифты и CSS в критическом пути

### Что обнаружено

Замер на живом `https://mastera.ge/ru/tbilisi/santehnik-tbilisi/`:

```
TTFB ................... 1020 мс
style.css .......... 1029 → 1516 мс  (487 мс, блокирует рендер)
service.css ........ 1029 → 1526 мс  (497 мс, блокирует рендер)
шрифты (5 файлов) .. 1548 → 1645 мс  (старт только после CSS!)
FCP .................... 1988 мс
LCP .................... 1988 мс  (элемент DIV.service-hero)
CLS .................... 0.029 ✓
```

Три независимые проблемы, все в цепочке загрузки:

**(а) Пять начертаний Montserrat грузятся разом — 510 КБ.**
В `style.css:4-46` объявлено 5 `@font-face` (400/500/600/700/900), каждый ~100 КБ.
Браузер качает все пять, и ни один не имеет `preload`:
```
grep -c 'rel="preload".*font' ru/index.html → 0
```
Шрифты стартуют на **1548 мс** — браузер узнаёт о них только после разбора CSS.
Это классическая цепочка `HTML → CSS → font`, самая дорогая в CWV.

**(б) `service.css` блокирует рендер на 105 лендингах.**
На главной он подключён правильно — через `media="print" onload`:
```html
<!-- ru/index.html — ХОРОШО -->
<link rel="stylesheet" href="/service.css?v=31" media="print" onload="this.media='all'">
```
Но на лендингах — обычным блокирующим тегом:
```html
<!-- ru/tbilisi/santehnik-tbilisi/index.html:хвост head — ПЛОХО -->
<link rel="stylesheet" href="/service.css?v=31">
```
И именно на лендингах LCP-элемент — `.service-hero`, который описан **в этом самом
`service.css`** (`service.css:6`). То есть первый экран ждёт файл, который на главной
признан некритичным. Лендинги — главный поисковый трафик, и они медленнее главной.

**(в) Нет `preconnect` к Google Analytics.**
```
grep -c 'preconnect|dns-prefetch' → 0 на всех страницах
```
На главной GA отложен до первого скролла (сделано грамотно, `ru/index.html`),
а на лендингах `gtag/js` грузится **синхронно двумя тегами сразу** с `async`:
```html
<script async src="https://www.googletagmanager.com/gtag/js?id=G-7SLML317LT"></script>
<script async src="https://www.googletagmanager.com/gtag/js?id=AW-17979861714"></script>
```
Лендинги не получили ту оптимизацию, что главная.

### Критичность: **ВЫСОКАЯ**

LCP 1988 мс — на грани «нужно улучшить» (порог 2500 мс для «хорошо», но это замер
с быстрого канала; на мобильном 4G в Грузии будет 3.5–4.5 с). Google использует CWV
как фактор ранжирования, а для коммерческой ниши с высокой конкуренцией это
осязаемые позиции.

### Пошаговая инструкция

**Шаг 1. Сократить шрифты с 5 начертаний до 2.**

Реально на странице нужны `400` (текст) и `900` (заголовки, `.hero-title`).
Веса 500/600/700 браузер синтезирует из 400 почти без потери качества —
а это экономит **300 КБ**.

В `style.css` удалить блоки `@font-face` для 500, 600, 700 (строки 12–34) и
добавить `size-adjust`, чтобы подмена не дала скачка:

```css
/* Два начертания вместо пяти: 500/600/700 браузер синтезирует из 400.
   Экономия 300 КБ — шрифты были самой тяжёлой частью первого экрана. */
@font-face {
    font-family: 'Montserrat';
    font-weight: 400 700;      /* вариативный диапазон: один файл на 400–700 */
    font-style: normal;
    font-display: swap;
    src: url('./fonts/montserrat-regular.woff2') format('woff2');
}

@font-face {
    font-family: 'Montserrat';
    font-weight: 900;
    font-style: normal;
    font-display: swap;
    src: url('./fonts/montserrat-black.woff2') format('woff2');
}
```

**Шаг 2. Добавить `preload` обоих шрифтов — во все 108 страниц.**

Ставить сразу после `<meta name="viewport">`, ДО подключения CSS:

```html
  <!-- Шрифты в критическом пути: без preload браузер узнаёт о них только
       после разбора style.css и начинает качать на 1548 мс. -->
  <link rel="preload" href="/fonts/montserrat-regular.woff2" as="font"
        type="font/woff2" crossorigin>
  <link rel="preload" href="/fonts/montserrat-black.woff2" as="font"
        type="font/woff2" crossorigin>
```

⚠️ `crossorigin` обязателен даже для своего домена — без него браузер скачает
файл **дважды** (preload в анонимном режиме, CSS в credentialed).

Скрипт для массовой правки (кладите в корень сайта, запуск `python add-preload.py`):

```python
#!/usr/bin/env python3
# Добавляет preload шрифтов во все HTML-страницы сайта.
# Идемпотентен: если preload уже стоит, файл не трогается.
import pathlib, re

PRELOAD = '''  <!-- Шрифты в критическом пути: без preload браузер узнаёт о них
       только после разбора style.css. -->
  <link rel="preload" href="/fonts/montserrat-regular.woff2" as="font" type="font/woff2" crossorigin>
  <link rel="preload" href="/fonts/montserrat-black.woff2" as="font" type="font/woff2" crossorigin>
'''

root = pathlib.Path('.')
changed = 0
for f in root.rglob('index.html'):
    if '.git' in f.parts:
        continue
    s = f.read_text(encoding='utf-8')
    if 'montserrat-regular.woff2" as="font' in s:
        continue                                   # уже добавлено
    # Вставляем сразу после строки с viewport — она есть на всех страницах.
    new = re.sub(r'(<meta name="viewport"[^>]*>\n)', r'\1' + PRELOAD, s, count=1)
    if new != s:
        f.write_text(new, encoding='utf-8')
        changed += 1
print(f'preload добавлен в {changed} файлов')
```

**Шаг 3. Снять блокировку `service.css` на лендингах.**

Перенести на лендинги ту же схему, что уже работает на главной. Но так как

```html
  <!-- Остальной service.css не нужен первому экрану — без блокировки рендера -->
```

**Шаг 4. Отложить GA на лендингах — как на главной.**

Заменить на всех 105 лендингах два `<script async src="...gtag...">` на тот же
отложенный загрузчик, что стоит в `ru/index.html` (блок «Google Analytics

**Шаг 5. Поднять версию статики.**


⚠️ Обязательно: вы правите `style.css` и HTML. Без этого вернувшиеся посетители

И помните правило из `sw.js` (комментарий v31): проверять новый `?v=` только

## 1.2. Кэширование: `max-age=14400` на версионированных файлах

### Что обнаружено

```
GET /script.js?v=31  → Cache-Control: max-age=14400   (4 часа)
GET /style.css?v=31  → Cache-Control: max-age=14400
GET /fonts/montserrat-regular.woff2 → max-age=14400
GET /image/hero-bg.webp → max-age=14400
```

Файлы версионированы через `?v=`, то есть **новая версия — это новый URL**.
При такой схеме держать 4 часа бессмысленно: повторный визит через 5 часов
заново качает 510 КБ шрифтов и 150 КБ скриптов, хотя они не менялись.

Шрифты вообще не версионированы и при этом живут 4 часа — худший случай.

### Критичность: **СРЕДНЯЯ**
Прямо на позиции не влияет, но бьёт по CWV повторных визитов и по поведенческим
(в Яндексе — фактор ранжирования).

### Пошаговая инструкция

Cloudflare → Rules → **Cache Rules**. Создать правило:

| Поле | Значение |
|------|----------|
| Name | `static-immutable` |
| If incoming requests match | Custom filter expression |
| Expression | `(http.request.uri.path matches "\.(css\|js\|woff2\|webp\|png\|jpg\|svg\|ico)$")` |
| Cache eligibility | Eligible for cache |
| Edge TTL | Override origin → **1 year** |
| Browser TTL | Override origin → **1 year** |

Затем Rules → **Transform Rules → Modify Response Header**, добавить:
```
Set static: Cache-Control = public, max-age=31536000, immutable
```
с тем же выражением.

⚠️ `immutable` безопасен **только** при версионировании. У вас `?v=` есть
у `css/js`, но **нет у шрифтов и картинок**. Поэтому перед этим шагом добавьте
версию и им — в `style.css`:

```css
src: url('./fonts/montserrat-regular.woff2?v=32') format('woff2');
```

и внесите `og-preview-*.jpg`, `hero-bg.webp` в `OG_IMAGES`/список `bump-version.py`
(механизм уже есть — см. комментарий v30 в `sw.js`).

**HTML оставить как есть** (`max-age=600`) — он должен обновляться быстро.

## 1.3. `robots.txt` — не указан хост и нет Clean-param для Яндекса

### Что обнаружено

```
User-agent: *
Allow: /
Sitemap: https://mastera.ge/sitemap.xml
```

Файл корректен и осознанно не закрывает служебные страницы — в комментарии верно
объяснено, почему `noindex` лучше `Disallow` (краулер должен увидеть мету).
Это правильное решение, менять не нужно.

Чего не хватает:
1. Нет директив для AI-краулеров — для сервисной ниши это уже источник трафика
   (ChatGPT/Perplexity рекомендуют локальные сервисы).
2. Нет `Clean-param` для Яндекса — а у вас на сайте есть UTM-трафик (есть `AW-`
   конверсии Google Ads), и Яндекс плодит дубли по UTM-меткам.

### Критичность: **СРЕДНЯЯ**

### Пошаговая инструкция

Заменить `robots.txt` целиком:

```
# robots.txt для «Мастера Грузии» (mastera.ge)

# Сайт полностью открыт для индексации.
# Служебные страницы (корневой language-router, /<lang>/fb/, 404)
# закрыты метатегом noindex в самой разметке, а не здесь:
# robots.txt запретил бы их СКАНИРОВАНИЕ, и тогда краулер не увидел бы
# noindex — страница могла бы попасть в выдачу без описания.
User-agent: *
Allow: /

# Яндекс склеивает дубли по UTM-меткам сам, только если ему сказать,
# какие параметры не меняют содержимое страницы. Без этого /ru/?utm_source=fb
# и /ru/ считаются разными страницами и делят между собой вес.
User-agent: Yandex
Allow: /
Clean-param: utm_source&utm_medium&utm_campaign&utm_term&utm_content&gclid&fbclid&yclid

# AI-ассистенты: для сервиса «вызвать мастера» это живой источник заявок —
# люди спрашивают «где найти сантехника в Тбилиси» у чат-ботов.
User-agent: GPTBot
Allow: /

User-agent: OAI-SearchBot
Allow: /

User-agent: PerplexityBot
Allow: /

User-agent: ClaudeBot
Allow: /

# Карта сайта — основной источник URL для краулеров.
Sitemap: https://mastera.ge/sitemap.xml
```

## 1.4. `sitemap.xml` — 108 URL против 109 реальных, нет hreflang-аннотаций

### Что обнаружено

**(а) Расхождение в количестве.** В sitemap 108 `<loc>`, а индексируемых страниц
на диске — 109 (116 HTML минус `404.html`, `google.html`, 2× `yandex_*.html`,
3× `/<lang>/fb/`, корневой `index.html` = 108). Расхождений нет.
Фактически в sitemap отсутствуют страницы, которых **нет на диске** — см. 1.4(б).

**(б) Главное: нет `/<lang>/tbilisi/` — и файла тоже нет.**

Проверено на живом сайте:
```
https://mastera.ge/ru/batumi/   → 200 ✓
https://mastera.ge/ru/tbilisi/  → 404 ✗
```
```
OK   ru/batumi/index.html      НЕТ  ru/tbilisi/index.html
OK   en/batumi/index.html      НЕТ  en/tbilisi/index.html
OK   ge/batumi/index.html      НЕТ  ge/tbilisi/index.html
```

У Батуми есть городской хаб, у Тбилиси по этому адресу — 404. Это **не дефект**:
хабом Тбилиси служит сама главная `/ru/` («Мастера в Тбилиси», все 19 ссылок на
лендинги, все 10 районов). Отдельная `/ru/tbilisi/` стала бы её дублем.

Чинится редиректом, а не новой страницей — разбор в разделе 2.1.

**(в) Нет hreflang внутри sitemap.** Для трёхъязычного сайта Google рекомендует
дублировать языковые связи в sitemap (`xhtml:link`) — это ускоряет склейку
языковых версий. В HTML hreflang есть и корректен, но sitemap-дубль даёт
дополнительный сигнал.

**(г) Нет `lastmod`?** — проверьте; если `<lastmod>` стоит одной датой у всех
страниц, Google его игнорирует.

### Критичность: **СРЕДНЯЯ** (пункты «в», «г»; «б» — низкая, см. 2.1)

### Пошаговая инструкция

Шаг 1 — настроить редирект `/<lang>/tbilisi/` → `/<lang>/` (раздел 2.1).
В `sitemap.xml` эти адреса не вносятся: страниц по ним нет и быть не должно.

Шаг 2 — добавить hreflang-аннотации к существующим записям:

```xml
  <url>
    <loc>https://mastera.ge/ru/tbilisi/santehnik-tbilisi/</loc>
    <xhtml:link rel="alternate" hreflang="ru" href="https://mastera.ge/ru/tbilisi/santehnik-tbilisi/"/>
    <xhtml:link rel="alternate" hreflang="ka" href="https://mastera.ge/ge/tbilisi/santehnik-tbilisi/"/>
    <xhtml:link rel="alternate" hreflang="en" href="https://mastera.ge/en/tbilisi/santehnik-tbilisi/"/>
    <xhtml:link rel="alternate" hreflang="x-default" href="https://mastera.ge/ru/tbilisi/santehnik-tbilisi/"/>
    <lastmod>2026-10-24</lastmod>
    <changefreq>weekly</changefreq>
    <priority>0.8</priority>
  </url>
```

⚠️ Для `xhtml:link` нужно объявить namespace в корневом теге:
```xml
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9"
        xmlns:xhtml="http://www.w3.org/1999/xhtml">
```

Шаг 3 — скрипт сверки sitemap с диском (запускать перед каждым деплоем):

```python
#!/usr/bin/env python3
# Сверяет sitemap.xml с реальными файлами: ловит и забытые страницы,
# и мёртвые URL. Расхождение тихое — страница просто не индексируется.
import pathlib, re, sys

root = pathlib.Path('.')
sitemap = (root / 'sitemap.xml').read_text(encoding='utf-8')
in_map = {m.replace('https://mastera.ge', '').rstrip('/') or '/'
          for m in re.findall(r'<loc>(.*?)</loc>', sitemap)}

# Страницы с диска, кроме служебных (noindex) и технических
SKIP = {'404.html', 'google.html', 'index.html'}
on_disk = set()
for f in root.rglob('index.html'):
    if '.git' in f.parts:
        continue
    url = '/' + str(f.parent.as_posix()).replace('.', '').strip('/')
    url = url.rstrip('/') or '/'
    s = f.read_text(encoding='utf-8')
    if 'noindex' in s:           # /<lang>/fb/ и корневой роутер
        continue
    on_disk.add(url)

missing = on_disk - in_map
dead = in_map - on_disk - {'/'}
for u in sorted(missing):
    print(f'НЕТ В SITEMAP: {u}')
for u in sorted(dead):
    print(f'НЕТ ФАЙЛА (мёртвый URL в sitemap): {u}')
if missing or dead:
    sys.exit(1)
print(f'OK: {len(in_map)} URL, расхождений нет')
```

## 1.5. Микроразметка: нет `AggregateRating` — звёзды в сниппете потеряны

При этом на страницах **физически есть отзывы** — в `ru/index.html` три карточки:

Также нет `Organization` + `WebSite` — из-за чего Google не строит
knowledge-panel и не показывает sitelinks-searchbox.

### Критичность: **ВЫСОКАЯ**

### Пошаговая инструкция

**⚠️ Юридическое предупреждение, прочитать до внедрения.**
`AggregateRating` разрешено размечать **только по реальным отзывам**, которые
видны на той же странице. Google накладывает за выдуманные рейтинги ручные
санкции (Spammy Structured Markup), и восстановление занимает месяцы. У вас в
боте есть реальные оценки мастеров (`users.rating`, старт 4.5) — берите цифры
оттуда и отражайте их в видимом блоке на странице. Если реальных отзывов на
странице нет — **не размечайте**, вместо этого сначала соберите отзывы.

**Шаг 1. `Organization` + `WebSite` — добавить на три главные (`/ru/`, `/ge/`, `/en/`).**

Это безопасно и не требует отзывов. Добавить в существующий JSON-LD-массив:

```json
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "@id": "https://mastera.ge/#organization",
  "name": "Мастера Грузии",
  "alternateName": ["Mastera", "Masters Georgia", "ოსტატები საქართველოში"],
  "url": "https://mastera.ge/",
  "logo": {
    "@type": "ImageObject",
    "url": "https://mastera.ge/image/web-app-manifest-512x512.png",
    "width": 512,
    "height": 512
  },
  "contactPoint": {
    "@type": "ContactPoint",
    "telephone": "+995557645196",
    "contactType": "customer service",
    "areaServed": ["GE"],
    "availableLanguage": ["ru", "ka", "en"]
  },
  "sameAs": [
    "https://www.facebook.com/profile.php?id=61595113524507",
    "https://t.me/masterasupport"
  ]
},
{
  "@context": "https://schema.org",
  "@type": "WebSite",
  "@id": "https://mastera.ge/#website",
```

**Шаг 2. `AggregateRating` — только с реальными цифрами из бота.**

Добавить **внутрь** существующего `LocalBusiness` на главных:

```json

  "ratingValue": "4.8",
```

```sql
-- Средний рейтинг и число мастеров с оценками — честная база для AggregateRating.
SELECT ROUND(AVG(rating), 1) AS rating_value,
       COUNT(*)              AS review_count
FROM users
WHERE is_master = 1 AND rating IS NOT NULL AND completed_orders > 0;
```

⚠️ И обязательно покажите эти же числа **видимым текстом** на странице
(«Средняя оценка мастеров 4.8 из 5 — по 127 мастерам»). Разметка без видимого

Так как карточки уже в HTML, разметьте их микроданными прямо в вёрстке —

## 1.6. Изображения: нет `width`/`height`, два `<img>` без `alt`

### Что обнаружено

Замер DOM на живой странице:
```json
[
  {"src":"/image/whatsapp-icon.png","w":null,"h":null,"loading":null,"alt":""},
  {"src":"/image/telegram-icon.png","w":null,"h":null,"loading":null,"alt":""},
  {"src":"/image/telegram-icon.png","w":null,"h":null,"loading":"lazy","alt":"Telegram"},
  {"src":"/image/whatsapp-icon.png","w":null,"h":null,"loading":"lazy","alt":"WhatsApp"}
]
```

1. **Ни у одного `<img>` нет `width`/`height`** — браузер не может зарезервировать
   место, отсюда CLS. Сейчас CLS 0.029 (зелёный) только потому, что картинок мало
   и они маленькие.
2. **Два `<img>` с пустым `alt=""`** — это иконки в плавающей кнопке. Для чисто
   декоративных `alt=""` корректен, но эти — внутри кликабельной кнопки связи,
   и скринридер прочитает её как «ссылка» без названия.
3. `telegram-icon.png` — **27 КБ PNG**, `whatsapp-icon.png` — 11.5 КБ.
   Для иконок 40×40 это в 10 раз больше нужного; WebP дал бы ~2 КБ.
4. Одна картинка **вылезает за вьюпорт** на мобильном: `right: 378px` при
   `innerWidth: 375` (горизонтального скролла нет, обрезается, но это признак
   неточной вёрстки FAB).

### Критичность: **СРЕДНЯЯ**

### Пошаговая инструкция

```html
<!-- Размеры обязательны: без них браузер не резервирует место под картинку
     и верстка дёргается при загрузке (CLS). -->
<img src="/image/whatsapp-icon.webp" alt="Написать в WhatsApp"
     width="40" height="40" loading="lazy" decoding="async">
<img src="/image/telegram-icon.webp" alt="Написать в Telegram"
     width="40" height="40" loading="lazy" decoding="async">
```

Конвертация (нужен `cwebp` или ImageMagick):
```bash
cwebp -q 85 -resize 80 80 image/telegram-icon.png -o image/telegram-icon.webp
cwebp -q 85 -resize 80 80 image/whatsapp-icon.png -o image/whatsapp-icon.webp
```
(80×80 — двойной размер под Retina при отображении 40×40.)

⚠️ Иконки прописаны в `script.js` (плавающая кнопка строится скриптом) —
правьте и там, иначе половина иконок останется PNG.

```css
        display: none;
    }

    /* Hero лендинга начинается сразу под шапкой */

        padding-top: 24px;
    }
}
```

⚠️ Названия классов приведены по смыслу — сверьтесь с реальными в `style.css`
(блок шапки) перед правкой. Цель замера после правки: `h1rect.top < 300`.

# БЛОК 2. СТРУКТУРА И ВНУТРЕННЕЕ SEO

## 2.1. `/<lang>/tbilisi/` отдаёт 404 — нужен редирект, а НЕ новая страница

> ⚠️ **Исправлено 27.10.2026.** В первой редакции этот раздел советовал создать
> хабы `/<lang>/tbilisi/` по образцу `/<lang>/batumi/` и называл это «находкой
> №1». **Совет был неверный**, и владелец справедливо его отклонил: такая
> страница стала бы дублем главной. Ниже — исправленный разбор.

### Что обнаружено

```
https://mastera.ge/ru/batumi/   → 200
https://mastera.ge/ru/tbilisi/  → 404
```

Асимметрия есть, но она **не дефект**. Главная `/ru/` уже и есть хаб Тбилиси:

| Элемент главной `/ru/` | Значение |
|---|---|
| `<title>` | Мастера **в Тбилиси** — сервис подбора специалиста |
| `<h1>` | Сервис подбора мастеров **Тбилиси** |
| H2 | Мастера работают во всех районах **Тбилиси** (все 10 районов) |
| Ссылок на лендинги Тбилиси | **19** — полный набор |
| FAQ | «В каких районах Тбилиси работают мастера?» |

Батуми понадобился отдельный хаб ровно потому, что он **второй** город и на
главной не представлен. Тбилиси — основной, и его хаб это главная.

**Создавать `/ru/tbilisi/` нельзя:** страница повторила бы те же 19 ссылок, те
же районы, тот же FAQ и ту же форму, отличаясь парой строк текста. Это дубль,
который отнимает вес у главной и конкурирует с ней за одни и те же запросы —
ровно то, от чего предостерегает раздел 2.3 про doorway pages.

Реальная проблема одна, и она узкая: **краулер ходит по адресу `/ru/tbilisi/`**
(Googlebot обрезает URL по сегментам, обходя `/ru/tbilisi/santehnik-tbilisi/`)
и получает 404.

### Критичность: **НИЗКАЯ**

404 на несуществующем промежуточном сегменте — не ошибка сайта, Google такие
адреса просто отбрасывает. Чинить стоит ради аккуратности, а не ради позиций.

### Пошаговая инструкция

Cloudflare → Rules → **Redirect Rules**. Проще всего три статических правила:

| Если путь равен | Редирект 301 на |
|---|---|
| `/ru/tbilisi/` и `/ru/tbilisi` | `https://mastera.ge/ru/` |
| `/ge/tbilisi/` и `/ge/tbilisi` | `https://mastera.ge/ge/` |
| `/en/tbilisi/` и `/en/tbilisi` | `https://mastera.ge/en/` |

Status code — **301** (постоянный), Preserve query string — да.

⚠️ Редирект ведёт на языковую главную, а **не** на
`/ru/tbilisi/master-na-chas-tbilisi/`: главная и есть страница города, а
лендинг — одна из услуг на ней.

### Что из прежней редакции всё-таки верно

Один пункт остаётся в силе, и к хабам он не относится — **куда ведут логотип
и кнопка города**. Проверено по файлам:

| Страница | Логотип ведёт на | Кнопка города |
|---|---|---|
| `/ru/batumi/santehnik-batumi/` | `/ru/batumi/` — хаб города | `/ru/batumi/` |
| `/ru/tbilisi/santehnik-tbilisi/` | `/ru/` | `/ru/` |

Это **уже корректно**: обе ссылки ведут на хаб своего города, просто для
Тбилиси хаб — это `/ru/`. Правок не требуется.

### Ожидаемый эффект

Устранение 404 на служебном адресе. На позиции влияния практически нет —
в отличие от того, что утверждала первая редакция этого раздела.

## 2.3. Каких посадочных страниц критически не хватает

### Что обнаружено

Текущее покрытие — 109 страниц, 3 языка:

| Город | Услуги | Районы | Хаб |
|-------|--------|--------|-----|
| Тбилиси | 8 + «мастер на час» = 9 | 10 из 10 ✓ | **нет** ✗ |
| Батуми | 8 + «мастер на час» = 9 | 5 из 5 ✓ | есть ✓ |

Покрытие услуг и районов **полное** — это сделано хорошо. Но структура покрывает
только две оси: «услуга × город» и «район × мастер на час». Не хватает трёх типов
страниц, каждый из которых закрывает отдельный класс запросов.

### Чего не хватает — по приоритету

**(1) Срочные/аварийные страницы** — высокомаржинальный и самый конверсионный
сегмент. В нише бытовых услуг «срочно» = готовность платить больше и решать
сейчас. Запросы: «аварийный сантехник Тбилиси», «срочно электрик Тбилиси
круглосуточно», «прорвало трубу Тбилиси что делать».

У вас для этого **уже всё есть**: в форме заявки есть галочка `urgent`
(контракт с ботом, поле `urgent` → пометка «🚨 СРОЧНО»), а в FAQ сантехника
уже лежит готовый ответ «Что делать если прорвало трубу». Отдельной страницы нет.

Рекомендую 4 страницы × 3 языка = 12:
```
/ru/tbilisi/avariynyy-santehnik-tbilisi/      Аварийный сантехник 24/7
/ru/tbilisi/avariynyy-elektrik-tbilisi/       Аварийный электрик 24/7
/ru/batumi/avariynyy-santehnik-batumi/
/ru/batumi/avariynyy-elektrik-batumi/
```

**(2) Страница цен** — 3 страницы (`/ru/ceny/`, `/ge/`, `/en/`). Запрос «сколько
стоит вызвать сантехника в Тбилиси» — информационный вход в воронку. Прайс-блоки
у вас уже есть на каждом лендинге (`class="price-table"`, 8 строк), а сводной
страницы нет. Плюс это идеальное место для `Offer`-разметки.

## 3.2. 🔴 Нет блока гарантий — а это ключевое возражение ниши

Слово «гарантия» не встречается **ни разу** на всём сайте.

Для сервиса, где незнакомый человек приходит к вам домой и берёт деньги за

- Рейтинг мастера (старт 4.5, `config.limits.low_rating_threshold` = 2.8 —

Это сильные аргументы, не вынесенные на сайт.

## 3.3. Мультиязычность — технически сделана правильно

### Что обнаружено

Это один из самых качественных блоков сайта. Проверено фактически:

**hreflang взаимный и полный** на всех 108 страницах:
```html
<!-- /ge/tbilisi/santehnik-tbilisi/ -->
<link rel="alternate" hreflang="ru" href="https://mastera.ge/ru/tbilisi/santehnik-tbilisi/">
<link rel="alternate" hreflang="ka" href="https://mastera.ge/ge/tbilisi/santehnik-tbilisi/">
<link rel="alternate" hreflang="en" href="https://mastera.ge/en/tbilisi/santehnik-tbilisi/">
<link rel="alternate" hreflang="x-default" href="https://mastera.ge/ru/tbilisi/santehnik-tbilisi/">
<link rel="canonical" href="https://mastera.ge/ge/tbilisi/santehnik-tbilisi/">
```
Все три версии ссылаются на одинаковый набор, каждая включает себя,
canonical самоссылочный, `x-default` есть. Это ровно так, как требует Google.

**Контент переведён по-настоящему**, не транслитом:
```
GE: <html lang="ka"> | სანტექნიკოსი თბილისში — შეუკვეთეთ სპეციალისტი | Mastera
EN: <html lang="en"> | Plumber in Tbilisi — Book a Specialist | Mastera
```
H1 и тексты тоже переведены («Plumber in Tbilisi / Emergency call / Pipe leak,
clog, broken faucet»).

**Корневой роутер сделан корректно:** `index.html` определяет язык по
`navigator.language`, закрыт `noindex, follow`, и при этом даёт видимые ссылки
RUS/GEO/ENG — краулер пройдёт по ним, даже не исполняя JS.

### Одно замечание (низкий приоритет)

URL-слаги везде **русско-транслитные**, даже в английской и грузинской версиях:
```
/en/tbilisi/santehnik-tbilisi/     ← "santehnik", не "plumber"
/ge/tbilisi/master-na-chas-vake/   ← "master-na-chas", не "ostati-saatit"
```

Для англоязычного пользователя `/en/tbilisi/plumber-tbilisi/` был бы и понятнее,
и чуть релевантнее запросу. Но:

⚠️ **Менять это сейчас я не рекомендую.** Смена URL = 99 новых редиректов поверх
уже существующих 99 правил `legacy_urls_2026` в Cloudflare, временная просадка
позиций на 4–8 недель и риск ошибок в цепочках. Выигрыш от ключевика в URL
невелик (Google давно считает его слабым фактором). Если делать — то один раз
и целиком, после того как остальные пункты плана отработают и позиции
стабилизируются. Отмечаю как известный долг, а не как задачу.

### Что обнаружено

Что можно усилить:

### Критичность: **СРЕДНЯЯ**

### Пошаговая инструкция

**Шаг 1. Подпись под полем контакта:**

```html
<!-- Снятие тревоги у поля контакта: человек отдаёт телефон незнакомому
     сервису, и короткое объяснение, кто его увидит, заметно повышает

```

Это соответствует реальной механике: в боте контакт скрыт до взятия заявки
(см. контракт `/site/new-request`, поле `contact` — «скрыто до взятия заявки»).

**Шаг 2. Создать страницу политики конфиденциальности** — `/ru/privacy/`,
`/ge/privacy/`, `/en/privacy/`, закрыть `noindex` не нужно (пусть индексируется,
это сигнал доверия). Описать: какие данные собираются (имя, контакт, район,
описание задачи, фото), зачем (передача мастеру для выполнения заявки), кто
видит (мастер, взявший заявку; админ сервиса), срок хранения, как удалить

использует большинство сервисов и которая юридически обычно достаточна —
конклюдентное согласие сноской без чекбокса:

```html
<p class="form-note-small">
  Нажимая «Оставить заявку», вы соглашаетесь с
  <a href="/ru/privacy/">политикой обработки данных</a>.
```

# ⚠️ ЧЕГО ЭТОТ АУДИТ НЕ ПОКРЫВАЕТ

Честно о границах — чтобы вы не считали картину полной:

1. **Внешние ссылки и ссылочный профиль.** Не анализировались — нет доступа
   к Ahrefs/Majestic. Для коммерческой ниши в Грузии это может быть
   **решающим** фактором: при прочих равных выигрывает тот, на кого ссылаются.
   Начните с бесплатного: Google Business Profile (критично для локальной
   выдачи!), Яндекс.Бизнес, местные каталоги, 2GIS.

2. **Google Business Profile.** Для запросов «мастер рядом», «сантехник Тбилиси»
   карта выдаётся **выше органики**. Если профиля нет — это, возможно,
   бо́льшая потеря, чем всё перечисленное в отчёте. Проверьте в первую очередь.

3. **Реальные позиции и семантика.** Нет доступа к Search Console / Яндекс.Вебмастер.
   Приоритеты в плане расставлены по структурной логике, а не по вашим
   фактическим данным. Сверьтесь с Search Console: возможно, какие-то страницы
   уже в топе и трогать их не нужно.

4. **Конкуренты.** Не анализировались — какие страницы у них есть, какой объём
   контента, какие цены. Это отдельная работа.

5. **Замер CWV сделан с одной точки и один раз.** Для полевых данных нужен
   CrUX / Search Console → Core Web Vitals, где накапливается статистика
   по реальным посетителям с их устройств и каналов. Мои цифры — лабораторные.
