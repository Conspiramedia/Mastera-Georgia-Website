# Кэш статики в Cloudflare — что настроить и почему

Инструкция написана 26.10.2026 по замерам живого прода `mastera.ge`.
Делается **один раз**, в панели Cloudflare. В коде менять ничего не нужно.

---

## Зачем

Lighthouse показывает «Use efficient cache lifetimes — Est savings of 503 KiB»
— это самое крупное число во всём отчёте о производительности.

Сейчас GitHub Pages отдаёт всю статику с заголовком `max-age=14400`, то есть
**4 часа**:

| Файл | Cache-Control сейчас |
|------|----------------------|
| `/style.css?v=28` | `max-age=14400` |
| `/script.js?v=28` | `max-age=14400` |
| `/service.css?v=28` | `max-age=14400` |
| `/fonts/montserrat-*.woff2` | `max-age=14400` |
| `/image/*.webp`, `*.png` | `max-age=14400` |
| `/ru/`, `/en/`, `/ge/` (HTML) | `max-age=600` (10 минут) |

Своего заголовка GitHub Pages выставить не даёт — поэтому правим на стороне
Cloudflare.

### Что это даёт

1. **Посетителю быстрее.** Вернувшись через день, человек заново качает
   ~500 КБ, хотя ничего не изменилось. С годовым сроком — берёт из своего
   кэша мгновенно.
2. **Нам спокойнее при деплое.** Сейчас после каждого пуша несколько часов
   держится каша: один узел Cloudflare отдаёт новый файл, другой старый.
   Так было с `montserrat-black.woff2` (404 на части узлов) и с правкой
   размера кнопки.

### Почему это безопасно

Адреса статики **версионные**: `/style.css?v=28`, `/script.js?v=28`. Версию
поднимает `python bump-version.py` — он меняет номер в `sw.js` и во всех 108
HTML сразу. Новая версия = новый URL, и браузер скачивает его как незнакомый
файл, сколько бы ни был срок у старого.

Поэтому «год» здесь не риск, а именно то, для чего версионные адреса и
заводили.

⚠️ **Важное исключение — HTML.** Страницы (`/ru/`, `/en/`, `/ge/` и 105
лендингов) кэшировать надолго нельзя: в них лежат ссылки `?v=28`, и если
страница застрянет в кэше, посетитель не узнает о новой версии статики.
Для HTML оставляем короткий срок, как сейчас.

## Что сделать

### Шаг 1. Открыть правила кэширования

1. Зайти в [dash.cloudflare.com](https://dash.cloudflare.com)
2. Выбрать домен **mastera.ge**
3. Слева: **Caching** → **Cache Rules**
4. Нажать **Create rule**

### Шаг 2. Правило для статики

**Имя правила:** `Статика на год (адреса версионные)`

**Когда применять** — выбрать **Custom filter expression** и вставить
выражение (кнопка **Edit expression** переключает на текстовый ввод):

```
(http.request.uri.path.extension in {"css" "js" "woff2" "woff" "ttf" "webp" "png" "jpg" "jpeg" "gif" "svg" "ico"})
```

**Что делать (Then):**

| Настройка | Значение |
|-----------|----------|
| Cache eligibility | **Eligible for cache** |
| Edge TTL | **Ignore cache-control header and use this TTL** → `1 year` |
| Browser TTL | **Override origin** → `1 year` |

Сохранить — **Deploy**.

### Шаг 3. Проверить, что HTML под правило не попал

Выражение выше ловит только файлы с перечисленными расширениями. Адреса
страниц (`/ru/`, `/ru/tbilisi/master-na-chas-vake/`) расширения не имеют, так
что под правило не подпадают — останутся на прежних 10 минутах. Это то, что
нужно.

### Шаг 4. Сбросить текущий кэш

Чтобы новые заголовки разошлись сразу, а не через 4 часа:

**Caching** → **Configuration** → **Purge Everything** → подтвердить.

Разово это безопасно: следующий запрос каждого файла просто сходит на origin.

## Как проверить, что получилось

Через 1–2 минуты после сброса:

```bash
curl -sI "https://mastera.ge/style.css?v=28" | grep -iE "cache-control|cf-cache-status"
```

Должно стать `max-age=31536000` (это год в секундах) вместо `max-age=14400`.

Проверить, что HTML не задет:

```bash
curl -sI "https://mastera.ge/ru/" | grep -i "cache-control"
```

Здесь должно остаться `max-age=600`.

## Что изменится в работе

**Порядок деплоя не меняется.** Как и раньше:

```bash
python bump-version.py
```

затем коммит и пуш. Номер версии поднимется во всех 108 страницах, адреса
статики станут новыми, и посетители получат свежие файлы сразу — несмотря на
годовой срок у старых.

⚠️ **Забыть `bump-version.py` теперь дороже.** Раньше правка `script.js` или
`style.css` без поднятия версии доезжала до людей за 4 часа сама. С годовым
сроком она не доедет **вообще** — ни до посетителей, ни до их service worker.
Скрипт умеет проверять:

```bash
python bump-version.py --check
```

## Чего эта настройка не чинит

Из отчёта Lighthouse остаются:

- **Minify JS/CSS (~34 KiB)** — файлы отдаются неминифицированными. Выигрыш
  на деле меньше заявленного: brotli-сжатие по сети уже работает.
- **Minimize main-thread work 6.2 s, TBT 250 ms** — это причина, почему
  Performance 94, а не выше. Лечится дроблением `script.js` (~85 КБ), работа
  заметная и не бесплатная по риску.

Решение по ним отдельное; кэш — та часть, которая даётся даром.
